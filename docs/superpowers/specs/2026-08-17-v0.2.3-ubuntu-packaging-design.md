# proc-lens v0.2.3 Ubuntu Packaging Design

Date: 2026-08-17
Status: Approved architecture, packaging-only scope
Base: `main` at v0.2.2
Target branch: `feat/v0.2.3-ubuntu-packaging`

## Goal

Turn proc-lens into an installable Ubuntu desktop application without changing its process collection, classification, provenance, GPU, or TUI behavior.

A user should be able to download a `.deb` from GitHub Releases, install it, find **proc-lens** in the Ubuntu application menu, click it, and have a terminal open directly into the proc-lens TUI.

## Scope

v0.2.3 is packaging-only. It adds Debian packaging via `cargo-deb`, a Freedesktop `.desktop` launcher using `Terminal=true`, repository-owned SVG/PNG app icons, a local build script, package validation, a tag-triggered GitHub Release workflow that uploads the `.deb`, and README install/launch/uninstall documentation.

Out of scope: runtime/TUI behavior changes, kill/renice, AppImage/Snap/Flatpak, ARM64 release artifacts, GUI wrappers, and automatic package installation in CI.

## Installed paths

```text
/usr/bin/proc-lens
/usr/share/applications/proc-lens.desktop
/usr/share/icons/hicolor/scalable/apps/proc-lens.svg
/usr/share/icons/hicolor/256x256/apps/proc-lens.png
/usr/share/doc/proc-lens/README.md
/usr/share/doc/proc-lens/LICENSE
```

The package must not require Cargo/Rust at runtime.

## Debian packaging

Use `[package.metadata.deb]` in `Cargo.toml` and `cargo-deb`. Version becomes `0.2.3`; Debian revision remains the default `1`, yielding `proc-lens_0.2.3-1_amd64.deb` on the required Ubuntu x86_64 release runner. Assets explicitly include the existing release binary, desktop entry, SVG/PNG icons, README, and LICENSE. `depends = "$auto"` remains enabled for runtime shared-library dependency discovery.

## Desktop launcher

`packaging/proc-lens.desktop` uses `Type=Application`, `TryExec=proc-lens`, `Exec=proc-lens`, `Icon=proc-lens`, and `Terminal=true`, with English and zh_CN names/comments. It intentionally does not hard-code GNOME Terminal.

## Icon

The app icon is generic rather than ROS-branded: rounded app tile, terminal prompt motif (`>_`), lens/process-node motif, high contrast at small sizes, no third-party logo dependency. `packaging/icons/proc-lens.svg` is the source of truth; a 256x256 PNG is committed alongside it.

## Local build

`scripts/build-deb.sh` resolves repo root, requires `cargo-deb`, runs `./scripts/verify.sh`, runs `cargo deb`, asserts exactly one expected `.deb`, validates archive contents, and prints the package path. It never uses sudo and never installs tooling automatically.

## Package validation

Validation must assert these archive paths exist:

```text
/usr/bin/proc-lens
/usr/share/applications/proc-lens.desktop
/usr/share/icons/hicolor/scalable/apps/proc-lens.svg
/usr/share/icons/hicolor/256x256/apps/proc-lens.png
/usr/share/doc/proc-lens/README.md
/usr/share/doc/proc-lens/LICENSE
```

The desktop file must statically contain `Type=Application`, `Exec=proc-lens`, `Icon=proc-lens`, and `Terminal=true`.

## GitHub Release workflow

Add `.github/workflows/release.yml`, triggered only by tags matching `v*`, with `contents: write`. On Ubuntu 22.04 it checks out the tag, installs stable Rust and cargo-deb, runs the existing verification, builds and validates the `.deb`, then creates/updates the GitHub Release for the tag and uploads the deterministic `.deb` asset. Only amd64 is required in v0.2.3.

## CI strategy

Existing `ci.yml` remains the runtime quality gate. Packaging adds static metadata checks plus an Ubuntu package build/validation path. Rust 1.88 MSRV remains unchanged for the crate. Ordinary branch pushes cannot publish releases.

## Release procedure

After branch CI is green: merge/fast-forward to `main`, verify `main` CI, create annotated `v0.2.3` at the verified commit, let the tag trigger `release.yml`, then verify the GitHub Release and `.deb` asset. Release is incomplete until the release workflow is successful and the asset is visible.

## Acceptance criteria

- Cargo version is `0.2.3` with valid cargo-deb metadata
- `cargo deb` succeeds on Ubuntu 22.04
- package contains all required installed paths
- desktop entry has `Terminal=true`, `Exec=proc-lens`, `Icon=proc-lens`
- SVG and PNG icons are packaged
- fmt, Clippy, all-feature tests, CPU-only tests, release build, and Rust 1.88 MSRV remain green
- `main` is green after merge
- annotated `v0.2.3` points at verified main
- GitHub Release `v0.2.3` exists with `proc-lens_0.2.3-1_amd64.deb`
- no temporary release helper remains in `main`

## Failure handling

Packaging CI failure blocks tagging. Main CI failure blocks tagging. Release workflow failure leaves the tag in place but the release is reported incomplete until repaired. Packaging fixes must not weaken runtime tests or alter core behavior.
