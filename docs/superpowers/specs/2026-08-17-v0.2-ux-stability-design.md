# proc-lens v0.2 UX / Stability Design

## Goal

Make the TUI stable enough for continuous use while preserving the current lightweight 1 Hz process sampling model. The primary success criteria are: the selected process does not drift when rows reorder, the table no longer appears to jump every second, desktop applications are not misclassified as systemd services, and the user can pause the view to inspect a process without racing the refresh loop.

## Scope

This iteration implements the approved option 2: stable ordering, PID-anchored selection, classification fixes, pause/resume, project inference, shorter command rendering, page navigation, and a compact help view.

Out of scope for v0.2: process killing, renice, signals, mouse support, historical graphs, user-configurable themes, persistent configuration files, remote monitoring, Docker lifecycle controls, ROS graph inspection, and new external dependencies.

## Existing Problems

1. The TUI refreshes once per second and CPU sort is recomputed from the latest instantaneous process CPU sample. Small changes can reorder many rows at once.
2. `UiState` stores `selected: usize`, so the highlighted row is anchored to a position rather than a PID. If the table order changes, the highlight may point to a different process.
3. Any cgroup component ending in `.service` currently contributes SYSTEMD evidence. Desktop processes commonly inherit `user@<uid>.service`, causing Firefox, VS Code, GNOME Shell, WeChat, and similar processes to be mislabeled SYSTEMD.
4. The PROJECT column falls back to executable/process names for development and browser processes, so it often does not represent an actual project.
5. The main table renders the full command line, which creates visual noise and makes rows difficult to scan.
6. There is no pause state, manual refresh action, page navigation, or built-in help summary.

## Interaction Model

### Sampling and ordering

- Raw process/system sampling remains every 1 second.
- UI CPU values use an exponential moving average with `alpha = 0.35`:

  `smoothed = 0.35 * new + 0.65 * previous`

- A new PID starts with its first raw CPU value as its smoothed value.
- PID reuse must be protected by process identity (`pid + start_time_ticks`), not PID alone.
- Table order is recomputed every 2 seconds while running.
- Changing sort mode recomputes order immediately.
- Search changes recompute the filtered order immediately.
- CPU ordering uses 2 percentage-point bands to reduce churn. Processes in the same CPU band preserve their previous relative order. This gives a deterministic, transitive stable ordering instead of a comparator with non-transitive hysteresis.
- Memory, GPU, and PID sorts do not use CPU bands, but still follow the 2-second automatic reorder cadence.

### Selection

Replace row-index ownership with PID ownership.

`UiState` must track `selected_pid: Option<i32>` as the authoritative selection. A transient row index may be derived when rendering.

After any refresh/filter/sort:

1. If `selected_pid` still exists in the visible rows, keep it selected.
2. If the selected process exited or was filtered out, select the closest surviving row to the previous visual index.
3. If no visible rows remain, selection becomes `None`.
4. Enter opens detail for the selected PID, never merely "the row currently at index N".
5. Returning from detail restores the same selected PID when it still exists.

### Pause and manual refresh

- `Space`: toggle pause/resume.
- When paused, automatic sampling and automatic ordering stop. CPU/RAM/GPU gauges and the table are frozen together.
- Header shows `PAUSED` while paused.
- `r`: perform exactly one refresh using the same smoothing/order rules while staying paused.
- Resuming performs an immediate refresh, then resumes the normal 1-second sampling cadence.

### Navigation

- `j` / Down: move one row down.
- `k` / Up: move one row up.
- `PageDown`: move down by one visible page.
- `PageUp`: move up by one visible page.
- `Home`: first row.
- `End`: last row.
- `Enter`: detail.
- `/`: search.
- `Space`: pause/resume.
- `r`: manual refresh.
- `t`: tree mode.
- `c`, `m`, `g`, `p`: CPU, memory, GPU, PID sort.
- `?`: toggle help overlay.
- `Esc`: close help/detail/search before clearing the active filter.
- `q`: back from detail/help, otherwise quit.

The default footer remains compact:

`↑↓ move  Enter inspect  / search  Space pause  ? help`

The help overlay contains the full key map.

## Classification Design

### SYSTEMD rule correction

SYSTEMD classification must only be produced by a meaningful service unit, not the per-user service manager.

The following cgroup components are explicitly ignored as SYSTEMD evidence:

- `user@<uid>.service`
- `user.slice`
- `session-<id>.scope`
- `app.slice`

A service such as `todeskd.service`, `docker.service`, or another concrete non-user-manager `*.service` remains valid SYSTEMD evidence.

The priority order remains:

`ROS2 > CONTAINER > SYSTEMD > DEV > BROWSER > PROCESS`

With the false `user@<uid>.service` evidence removed, browser and development evidence can win naturally for desktop applications.

### Expected examples

- Firefox content process: `BROWSER`
- VS Code / code utility child: `DEV` when executable/name matches the development rule set
- clangd/cargo/cmake/ninja/colcon: `DEV`
- ROS2 node under a user session: `ROS2`
- ToDesk daemon under `todeskd.service`: `SYSTEMD`
- GNOME Shell without stronger category evidence: `PROCESS`

## Project Identity Design

PROJECT should represent a real workspace/project, not the process executable or inherited service manager.

Resolution order:

1. Existing ROS2 resolver workspace name.
2. For DEV processes, walk upward from `cwd` for at most 8 parents and stop at the first directory containing `.git`; use that directory basename.
3. For CONTAINER, keep the existing generic `container` label in v0.2.
4. For SYSTEMD, show the concrete service unit, excluding ignored user/session manager units.
5. BROWSER and PROCESS default to `-`.

No `git` subprocess is launched; project inference is filesystem-only.

Examples:

- `/home/yangxuan/proc-lens/src` -> `proc-lens`
- `/home/yangxuan/agt_navigation_v2/src/foo` -> `agt_navigation_v2` when that workspace root contains `.git`
- Firefox -> `-`
- GNOME Shell -> `-`
- `todeskd.service` -> `todeskd.service`

## Main Table Rendering

Keep the current columns:

`PID TYPE PROJECT CPU% RAM GPU% VRAM COMMAND`

Change COMMAND to a compact label:

- Tree mode: existing indented process name.
- Normal mode: process name plus only a small set of useful first arguments, truncated to fit the available column.
- The full command line remains available in detail view and `inspect` CLI output.

The table should prioritize scanability over exact reproduction of argv.

## Architecture

### `src/app.rs`

- Keep `AppSnapshot` as the raw/enriched data model.
- Change selection API from row-index ownership to PID ownership.
- Add project root inference helper for development processes.
- Keep CLI `snapshot` and `inspect` deterministic and independent from TUI smoothing.

### `src/ui/model.rs` (new)

Introduce a UI-only presentation model responsible for:

- smoothed CPU values keyed by `ProcessIdentity`
- current stable ordered PID list
- previous order ranks
- last reorder timestamp
- refresh integration
- selected PID reconciliation after process exit/filter changes

This keeps presentation stability out of the process collector and preserves raw process data for CLI use.

### `src/ui/mod.rs`

Own interaction timing and events:

- 1-second sampling deadline
- 2-second reorder deadline
- pause/resume
- manual refresh
- PageUp/PageDown/Home/End
- help toggle

The event poll may remain 100 ms, but redraw only occurs on input, refresh, reorder, resize, or overlay state changes.

### `src/ui/dashboard.rs`

Render from the presentation model instead of sorting the raw snapshot on every draw.

Add:

- `PAUSED` state in the header
- compact command labels
- compact footer
- help overlay

### `src/classifier/mod.rs` and `src/classifier/rules.rs`

Move systemd-unit eligibility into a dedicated helper so the ignored user-manager/session patterns are testable independently.

## Error Handling

- If a process exits between collection and render, omit it during reconciliation rather than surfacing an error.
- If project-root traversal hits an inaccessible parent, stop and return no inferred project.
- If GPU sampling fails, preserve the existing CPU/RAM-only behavior.
- Manual refresh failure keeps the last valid snapshot on screen and does not exit the TUI.
- Pause state must never mutate collector timing in a way that causes a burst of catch-up refreshes on resume.

## Tests

Add or update tests for all of the following:

1. `user@1000.service` does not classify an otherwise generic desktop process as SYSTEMD.
2. A concrete `todeskd.service` still classifies as SYSTEMD.
3. Firefox under `user@1000.service` classifies as BROWSER.
4. VS Code under `user@1000.service` classifies as DEV when development evidence exists.
5. ROS2 remains higher priority than service/dev/browser evidence.
6. DEV project inference finds the nearest `.git` ancestor within 8 levels.
7. Browser project label is `-`.
8. Selected PID survives a table reorder.
9. Selected PID exit falls back to the nearest surviving visual row.
10. EMA uses alpha 0.35 and resets for a new `ProcessIdentity` even when the PID is reused.
11. CPU band ordering preserves prior relative order inside the same 2 percentage-point band.
12. Sort mode change forces an immediate reorder.
13. Pause suppresses automatic refresh/reorder.
14. Manual refresh updates once while remaining paused.
15. Resume refreshes immediately.
16. PageUp/PageDown/Home/End update PID-based selection correctly.
17. Help overlay opens/closes without losing selection.
18. Compact command rendering truncates noisy Chromium/Firefox-style command lines while detail view retains the full command.

The existing CI gates remain mandatory:

- `cargo fmt --check`
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo test --all-targets --all-features`
- `cargo test --all-targets --no-default-features`
- `cargo build --release --all-features`
- Rust 1.88 MSRV check

## Acceptance Criteria

On the same desktop workload shown during v0.1 testing:

- The highlighted process remains the same PID while CPU values change and rows reorder.
- The list visibly reorders no more often than once every 2 seconds during CPU sort.
- Small CPU fluctuations within the same 2 percentage-point band do not swap row order.
- Space freezes the entire view; `r` performs one refresh; Space resumes.
- Firefox is BROWSER rather than SYSTEMD solely because it lives under `user@1000.service`.
- VS Code/build tools are DEV when their executable rules match.
- Generic desktop apps are PROCESS unless stronger evidence exists.
- PROJECT no longer displays `user@1000.service` for normal desktop apps.
- A development process launched inside the `proc-lens` repository displays PROJECT `proc-lens`.
- Full command/cgroup/provenance remains available in detail view.
- All existing and new CI checks pass on Ubuntu 22.04.
