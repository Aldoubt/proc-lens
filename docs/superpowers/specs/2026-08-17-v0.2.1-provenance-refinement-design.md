# proc-lens v0.2.1 provenance refinement design

## Goal

Refine the v0.2 stable TUI so generic browser/Electron/development subprocesses are attributed to the application or project that owns them, while preserving raw per-PID facts in detail views.

## Scope

v0.2.1 changes only three user-visible areas:

1. generic subprocess attribution from the nearest meaningful ancestor
2. PROJECT inference from the process/ancestor provenance chain
3. consistent ellipsis for long table labels

It does not add process killing, renice, grouping/collapsing rows, mouse input, history, persistence, external daemon queries, or new dependencies.

## Design choice

Three approaches were considered:

- hard-code child names such as `Isolated Web Co`: simple but brittle and browser-specific
- rewrite classification around a full process-family graph: powerful but too large for v0.2.1
- **derive provenance from the existing parent chain**: deterministic, generic, no extra system calls, and reuses data already collected by proc-lens

The third approach is selected.

## Provenance model

`EnrichedProcess` gains derived provenance fields:

```rust
pub struct ProcessProvenance {
    pub owner_pid: Option<i32>,
    pub owner_name: Option<String>,
    pub project_label: Option<String>,
}
```

`owner_pid` and `owner_name` identify the nearest ancestor whose direct classification explains a generic child. `project_label` stores the best project/application-family label found during enrichment.

Raw `ProcessSnapshot` fields remain unchanged. Parent chains remain unchanged. The detail view continues to show the current PID's original executable, cwd, command, cgroup, and parent chain.

## Inheritance rules

Inheritance applies only when the current process directly classifies as `PROCESS`.

Walk `parent_chain` from direct parent outward and choose the first ancestor with direct type:

```text
BROWSER
DEV
```

If the nearest meaningful ancestor is BROWSER:

- the child display classification becomes `BROWSER`
- provenance records the ancestor PID/name
- PROJECT becomes a normalized browser family label (`Firefox`, `Chrome`, `Chromium`, or `Brave`)
- classification evidence includes one inherited-provenance record

If the nearest meaningful ancestor is DEV:

- the child display classification becomes `DEV`
- provenance records the ancestor PID/name
- PROJECT uses the nearest Git project found from the current process and then ancestor cwd chain
- classification evidence includes one inherited-provenance record

Inheritance must never replace a current process already classified as ROS2, CONTAINER, SYSTEMD, DEV, or BROWSER.

## Browser family labels

Normalize browser ownership for the PROJECT column:

```text
firefox -> Firefox
chrome/google-chrome -> Chrome
chromium -> Chromium
brave -> Brave
```

This label is an application-family ownership label, not a filesystem project.

## Development project inference

For a direct or inherited DEV process, inspect cwd candidates in this order:

1. current process cwd
2. direct parent cwd
3. next ancestor cwd
4. continue outward through the existing parent chain

For each cwd, walk at most 8 parents looking for `.git`. The first discovered Git root wins. No `git` subprocess is spawned.

This lets VS Code or Electron utility processes inherit the project launched from a project shell even when the child process cwd is not itself inside the repository.

If no Git root is found, PROJECT remains `-`.

## Systemd behavior

Concrete systemd services keep existing behavior. They do not inherit browser/dev provenance, even when started from a desktop session.

`user@<uid>.service` remains ignored as concrete SYSTEMD evidence.

## Table command label

The command column keeps the current compact-command behavior.

For an inherited child, the raw process name remains visible. v0.2.1 does not replace the command with the owner name, because doing so would hide the actual PID identity. Ownership is conveyed by TYPE and PROJECT.

Example:

```text
PID     TYPE      PROJECT     COMMAND
7326    BROWSER   Firefox     firefox
65524   BROWSER   Firefox     Isolated Web Co
8736    DEV       proc-lens   code
```

## Long labels

All fixed-width TUI table labels that can exceed their column budget use a single Unicode ellipsis `…` instead of hard clipping.

PROJECT has a 24-character budget. A label longer than 24 characters becomes 23 visible characters plus `…`.

The full value remains available in the detail view or CLI output where applicable.

## Detail view

Add a compact provenance section when ownership is inherited:

```text
Provenance
Owner PID   : 7326
Owner       : firefox
Project     : Firefox
```

Do not duplicate the section for directly classified processes without an inherited owner.

## CPU semantics documentation

README/help text should state that:

- top CPU is whole-system utilization
- process CPU can represent per-process usage relative to CPU capacity and is not expected to sum directly to the top gauge

No CPU calculation changes are part of v0.2.1.

## Tests

Add deterministic tests for:

- generic Firefox Web Content child inherits BROWSER and project `Firefox`
- generic Code/Electron child inherits DEV
- inheritance uses the nearest meaningful ancestor
- direct SYSTEMD/ROS2 classifications are not overwritten
- DEV project lookup can find a Git root through ancestor cwd
- browser family normalization
- 24-character label truncation uses `…`
- detail output includes inherited owner provenance

All existing v0.2 tests must remain green.

## Verification

Final branch must pass:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
cargo test --all-targets --no-default-features
cargo build --release --all-features
```

GitHub Actions must also pass the Rust 1.88 MSRV check.

## Acceptance examples

A desktop similar to the observed Ubuntu workstation should move toward:

```text
65524  BROWSER  Firefox          12.3  1.10G  Isolated Web Co
9822   BROWSER  Firefox           7.9  1.64G  Isolated Web Co
8736   DEV      <git-project>     2.1   193M  code
2137   SYSTEMD  todeskd.service   3.5    23M  ToDesk_Service
```

A real concrete GNOME systemd user service may still show as SYSTEMD; v0.2.1 does not force every desktop process to PROCESS.
