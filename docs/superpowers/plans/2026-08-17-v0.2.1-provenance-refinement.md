# proc-lens v0.2.1 Provenance Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attribute generic browser/development subprocesses to their nearest meaningful ancestor, improve DEV project inference through ancestor cwd, and truncate fixed-width TUI labels with an ellipsis.

**Architecture:** Keep `/proc` collection and direct classification unchanged. Enrichment becomes a two-pass pipeline: first compute each PID's direct classification and parent chain, then derive inherited provenance only for direct `PROCESS` rows using already-collected ancestor data. Store derived ownership/project information on `EnrichedProcess` so rendering remains cheap and deterministic.

**Tech Stack:** Rust 2024, `/proc`, Ratatui, existing deterministic classifier, GitHub Actions, Rust 1.88 MSRV.

## Global Constraints

- Linux/Ubuntu remains the target; no new platform support.
- Rust minimum supported version remains 1.88.
- Add no new crates or external daemon/CLI queries.
- Only direct `PROCESS` may inherit `BROWSER` or `DEV`.
- ROS2, CONTAINER, SYSTEMD, direct DEV, and direct BROWSER must never be overwritten by provenance inheritance.
- Existing raw executable/cwd/command/cgroup/parent-chain details must remain visible.
- Git project discovery walks at most 8 filesystem parents per cwd candidate and never spawns `git`.
- Final fixed-width PROJECT display budget is 24 characters and uses Unicode `…`.

```rust
    } else if lower.contains("chromium") {
        Some("Chromium")
    } else if lower.contains("brave") {
        Some("Brave")
    } else if lower.contains("chrome") {
        Some("Chrome")
    } else {
        None
    }
}
```

Use the owner name first, then owner executable filename if needed. Store the normalized label in `provenance.project_label`.
